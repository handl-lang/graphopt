# Overview — where the kernel work is, and the M1 plan

**Date:** 2026-10-27 · for review

## 1 · The thesis

Hand-tuning kernels is expensive, so it is only bought for popular shapes
on popular hardware. A machine that proposes, prices and certifies kernels
can cover the long tail. The moat is not one fast kernel — it is the
referee (honest measurement), the collapsing cost per experiment, and
certification.

## 2 · What exists today

| layer | what | state |
|---|---|---|
| `kernel` / `engine` / `host` | closed six-combinator calculus, engines, plugin host | working |
| `kernelopt` | IR, `KERNEL_RULES`, sink, cost model, sieve, minting | working; composes, rarely invents |
| `graphopt` | LLM-graph optimizer, 6,291 tests, evidence ledger | working |
| `graphopt/bench/benchkit/regime.py` | deploy-regime referee (eviction, blocked rounds, roofline) | **new, tested** |
| `graphopt/bench/drivers/probes/awq/` | the int4 kernel + all P13–P18 probes | **new, demo-grade** |

## 3 · What this session proved

- **Kernel margin (valid):** our int4 GEMV beats `awq_gemm` cold on three
  of four layer shapes — **2.96× / 1.52× / 1.35×**, exact.
- **It reaches the model (valid):** substituted into vLLM with the
  checkpoint tensors snapshotted before repacking, output is
  **token-identical** and the model is **29.2 % faster** (1164.6 → 824.1 ms,
  25/25 paired rounds, decode, one 4 GB laptop GPU).
- **Three retractions:** a fake 3.3× (fp16 atomics), a fake −3.1 %
  (too few rounds), a fake −28.5 % (wrong AWQ nibble order). All caught by
  the harness, all published as retractions.
- **The bug worth remembering:** AWQ packs 8 int4 per int32 in the order
  `[0,4,1,5,2,6,3,7]`. My reference used the same wrong order, so it
  validated itself. *A self-written reference proves self-consistency, not
  correctness.*

**What is still not true: the machine did not find that kernel — I wrote
it.** It swept 48 configs of my design. Closing that gap is M1.

## 4 · The M1 plan (six items, ~4 days)

| # | build | home | gate |
|---|---|---|---|
| 1 | **ADR:** kernel IR enters as data, kernel stays closed | `host/project/adrs/` | accepted |
| 2 | **`lib-cuda-ir`** — ops, grades, costs, denotations (a handl **lib**) | new repo | every op has a signature, grade, cost, reference |
| 3 | **`kit-cuda`** — curated kit including that lib | new repo | kit assembles and loads |
| 4 | **`compile-triton`** — Rust engine: `Term` → Triton, `qgemv` × 4 `split_k` | new repo | 4 variants compile and run |
| 5 | **Equality gate vs `awq_gemm`** | `graphopt/bench` | cosine ≥ 0.9999, all variants |
| 6 | **Search driver** in `kernelopt` | `kernelopt` | emits a best kernel + routing row |

**M1 gate:** four variants generated from `Term`s, all exact, and at least
one within the hand kernel's **58.9 µs cold** on `down_proj`.
**Kill:** if a fixed lowering cannot match hand-written Triton on one
operator, generalising is wasted work — keep hand-writing kernels and use
the search only for configs.

## 5 · Architecture (corrected after review)

```
lib-cuda-ir  ──Terms (kit-declared ops)──▶  kernelopt  ──term──▶  compile-triton (Rust)
 (vocabulary,                                (enumerate, gate,          (Term → Triton)
  data)                                       price, choose)
                                                  │ chosen
                                                  ▼
                                        graphopt/bench (referee)
                                                  │ winner
                                                  ▼
                                        lib-cuda-qgemv  (M2)
```

Three corrections that shaped it: a **kit is a manifest of libs** (so
`lib-cuda-ir` + `kit-cuda`, not one thing); `compile-triton` is **Rust**
like the rest of the family; and **there is no new schema — the IR is
`Term`**, so certificate, sink, sieve and cost model all apply unchanged.

**Two-stage schedule, stated for attribution:** our IR picks blocks and
split; Triton picks pipelining, vectorization and layouts.

## 6 · Risks, and what they cost

| risk | counter |
|---|---|
| Triton codegen can't match hand-written Triton | M1 kill criterion — cheap to learn |
| cost model prunes winners | used only as a hard bound, never to rank |
| search rate-limited by compilation | compile cache before scaling past ~10³ candidates |
| overfitting to one GPU | every routing table ships with its calibration |
| silent wrongness | equality gate vs the **incumbent**, inside the timing path |
